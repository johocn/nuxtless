# 领域知识沉淀机制设计（配送档案样板 + 通用规范）

> 日期：2026-09-12
> 状态：设计定稿待审

## 1. 背景与痛点

配送档案相关的设计思路与实现知识散落在 `docs/superpowers` 下 6+ 份按日期命名的 spec/plan/manual 中。AI 下次遇到配送档案问题，需扫描多份历史文档 + 反复读源代码才能定位与修复，耗时长。

已有沉淀（`project_memory.md`「配送档案/自提点体系」节）每会话自动注入 AI 上下文，但：无「单一入口 + 代码位置地图」，无「现象→根因→代码点」映射，无领域级回归验证闭环。

## 2. 总体架构：三层 + 闭环

| 层 | 载体 | 读者 | 特点 |
|---|---|---|---|
| L1 速查卡 | `project_memory.md` 领域小节 | AI 每会话自动注入 | 一页摘要：关键结论 + 一行指针指向手册，零查找成本 |
| L2 领域手册 | `docs/domains/<domain>.md` | 人 + AI | 深度内容（7 章），主载体 |
| L3 来源 | 代码 + `docs/superpowers/specs\|plans\|manual` | AI 定位时深入 | 手册「文件地图」「历史索引」章直接指向 |

连接方式：速查卡（摘要）→ 一行指针 → 手册（文件地图/问题速查）→ 精确文件与符号 → 直达代码。将「扫 6+ 份文档」降为「读 1 页速查卡 + 1 份手册」。

## 3. 领域手册模板（7 章，可推广）

1. **概念模型** — 实体关系、关键术语、作用域规则
2. **文件地图（符号级）** — 每个相关文件路径 → 职责 → 关键导出符号/函数/组件（**不含行号**，防漂移；行号用 grep 现查）
3. **设计决策** — ADR 式「为什么这么做」
4. **常见坑** — 从 memory 迁入 + 补全（复现现象 → 根因 → 解法）
5. **问题速查（Bug 知识库）** — 现象 → 根因 → 代码点 → 回归脚本 四列映射表
6. **验证脚本清单** — 脚本路径 → 用途 → 运行命令
7. **历史文档索引** — 链接到相关 specs/plans/manual 具体文件

## 4. 精准修 Bug 四件套（补充）

针对「快速定位、精准修复、不用反复查源代码」：

### 4.1 Bug 知识库表（手册第 5 章）
以「现象 → 根因 → 代码点 → 回归脚本」四列组织，首批录入配送档案真实案例：
- 自由大路店在档案 1 误显示（应显示国信南山温泉酒店）→ methodConfigs.options.pickupLocationIds 与库不一致 → shipping-profile.service.ts 绑定逻辑 → query-t2-profiles-db.mjs
- 切换自提点被遗忘 → 切换状态未持久化同步 → BoxPickupBlock.vue / useOrderStore → verify-orderboxes.mjs
- t2 无配送档案 → 租户可见性规则缺自有档案 → pickup-location.service.ts applyVisibility → verify-admin-pickup-pool.mjs
- 非超管可改全局属性 → 权限校验缺口 → assertProfileGlobalPermissions → 单测 + verify-shipping-profile-global.mjs

**同类 bug 再出现时直接命中根因，无需重新分析。**

### 4.2 领域回归套件
每个领域一个一键回归脚本 `tmp/regress-<domain>.mjs`，串联该领域全部 verify-*.mjs 关键断言（抽离为可复用模块）。修复后用行为验证替代通读代码确认。

### 4.3 符号级文件地图（手册第 2 章）
每文件列出关键导出符号 + 一句话职责。AI 打开源文件前已知目标，用 `rg` 定位符号行号后**最小读取**（目标函数 ± 上下文 30 行），禁止通读大文件。

### 4.4 定位五步法（工程约定）
速查手册 → grep 符号（必要时 ast-grep 结构搜索）→ 最小读取 → 看回归测试 → 修复 + 跑回归验证。写入 `project_memory.md` 工程约定，约束 AI 行为防全仓库漫游。

## 5. 维护机制（保持最新）

- `docs/domains/README.md` 固化规范：何时建手册、章节模板、命名约定（`<domain>.md`）
