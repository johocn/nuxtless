# NShop C 端「逐箱结算」中国本地化设计（定稿）

> 关联 repo：`d:\zhao\nshop`（C 端 Nuxt）、`d:\zhao\vendure`（后端 cjk-plugin / coupon-plugin）
> 状态：定稿（含 13 条核心假设 + 地址字段对齐 + 邮编/邮箱归属 + city 修复 + 遗漏清单）
> 日期：2026-09-02

## 0. 背景与目标

- 现有结账已支持「多租户、租户内按物流档案分箱」，配送档案关联支付档案，箱已是一组共享物流档案的商品行。
- 但分箱只做了"壳"：结算页仍是"整单式"，未把每箱做成**用户可见、可独立操作**的结算单元。
- 本设计把结算页升级为**逐箱式**：每箱展示 租户名 + 配送档案名 + 本箱商品 + 本箱券/运费优惠 + 本箱小计；支持整箱/部分商品结算；支付支持合并 1 单或按箱拆单；除余额外实收**按商户分账**计入各商家账号。

## 1. 分箱与分组规则（沿用既有 + 明确）

1. **先按租户（商家）分箱优先**，不同租户必分箱；租户内再按配送档案分箱。
2. 即使共用同一配送档案，不同租户也**必分箱**，零交集。
3. 每箱是一组共享同一配送档案（服务方式、地址、支付白名单）的商品行。
4. 结算页按「群组」展示：**先按商家分区块 → 组内并列该商家各配送箱**；汇总单独列出每家商户分账 + 应付款总额。

## 2. 逐箱卡片 UI

- 每箱一张卡片（移动端纵向堆叠）。
- **箱标题直接用配送档案名**，不再用"配送组 N"；副标题标「租户名 + 档案类型（物流/自提）」。
- 箱内自上而下：
  1. **整箱勾选框**（默认全选该箱）；
  2. 物流箱 → 收货地址卡 + 配送方式单选；自提箱 → 自提点 + 联系人模块；
  3. **该箱商品明细行**（可勾选部分 / 数量步进 / 删除）；
  4. **该箱可用券、运费优惠、本箱小计**。

## 3. 商品行交互（结算粒度：整箱为主 + 部分可操作，防错）

- **整箱全选**：箱头勾选 = 该箱所有商品行全选/反选（常规场景直接整箱下单）。
- **部分选择**：每行独立勾选框，可只结算部分商品。
- **数量调整**：每行 `− 数量 ＋` 步进器（可加可减）。
- **删除**：每行「删除」按钮，移除该行（防错兜底）。
- 汇总、小计、券、运费**实时按已选项计算刷新**。
- 边界：某种商品不可拆分/需整行时，行内只允许全选该行；数量不得减到 0（禁用减号）。

## 4. 收货地址（逐箱、租户级地址簿、对齐 Vendure 字段）

### 4.1 后台字段对齐（Vendure `Address` 实体）

| 后端字段 | 类型 | 我们的字段 | 必填(前端物流) | 备注 |
|---|---|---|---|---|
| `fullName` | String | 收货人 | ✅ 必填 | 单一字段，不拆姓/名 |
| `phoneNumber` | String | 联系电话 | ✅ 必填 | |
| `country` | Country!(后端必填) | 国家 | ✅ | 用网页默认语言填充 |
| `streetLine1` | String!(后端必填) | 详细地址 | ✅ 必填 | 省市区街道并入此处 |
| `province` | String | 省 | ✅（高德选中） | |
| `city` | String | 市 | ✅（高德选中） | 区并入 city/streetLine1 |
| `postalCode` | String | 邮编 | ✅ **物流必填** | 国内物流面单要求；自提不需要 |
| `streetLine2` | String | 地址2 | 选填 | 默认可隐藏 |
| `company` | String | 公司 | 选填 | 默认可隐藏 |
| `defaultShippingAddress` | bool | 设为默认 | — | 地址簿首位=默认 |
| `defaultBillingAddress` | bool | — | — | 本设计不使用（合并单开票另行设计） |

- 后端真正硬必填只有 `streetLine1` + `country`；其余有默认值。
- **无独立 district(区)/street 字段**：区、街道并入 `streetLine1`（前端联动自动拼接）。
- **Address 不含邮箱、不含姓/名拆分**：
  - 邮箱 → `Customer.emailAddress`（客户档案层，不写入地址）。
  - 姓/名 → `Customer.firstName / lastName`（客户档案；收货人仍用 `fullName` 单一字段）。

### 4.2 国家 = 网页默认语言填充

- `localeToCountry`：`zh→CN`、`en→US`；频道可用国家不含该值 → 回退列表默认 `CN` → 列表首项。
- 国家默认值必须**先于提交校验**写入 `state.countryCode`，防止空国家。

### 4.3 省市区 = 高德地图反查填充（沿用 `AddressForm.vue`）

- 由 `locationStore.geo`（或坐标反查）触发 `preselectByLocation → cascadeGeo`，自动逐级选中 省→市→区，`formattedAddress` 预填详细地址。
- **city 提交报错修复（纳入本轮）**：
  - 根因：`syncState()` 用 `state.city = citySel.current` 覆盖，当从地址簿回填时 `applyExistingState()` 按中文名精确比对高德节点失败 → `citySel.current` 空 → 覆盖 `state.city` 为空 → 校验报"未选择城市"（此时下拉选项可见）。
  - 修复：
    1. 以 **adcode（高德区划码）**为主比对/存储，中文名兜底包含匹配；
    2. `syncState()` **仅当 `citySel.current` 非空时才覆盖** `state.city/province`，否则保留已存值；
    3. 提交时若仍缺选中，**回退到地址簿/状态下已有的省市区值**。

### 4.4 地址簿（租户级）CRUD + 分页

- 每个租户（收货账户）维护自己的物流配送地址列表。
- 能力：**默认地址 + 待选地址**；新增 / 修改 / 删除 全 CRUD。
- **条数 > 10 自动分页**（每页 5 条；≤10 单页展示）。
- 结算默认带入"默认地址"；「切换地址」打开地址簿选择或进入新增。
- 多个物流箱可各自指向不同地址（京东→家、顺丰→公司）。

## 5. 自提联系人（自提档案）

- 不同自提档案可配置「是否需要联系方式」（需 / 不需分开）。
- 需联系方式的箱：展示**默认联系人**（姓名 + 电话）；「切换联系人」→ 打开联系人簿选择或进入新增。
- 联系人簿：**默认 + 待选**；新增 / 修改 / 删除 全 CRUD；**条数 > 10 分页**（每页 5 条）。
- **联系人 = 收货人，仅姓名 + 电话，不需要邮箱**（与物流地址区分）。
- 联系人独立于地址存储（自提无物流地址）。

## 6. 配送方式（逐箱单选）

- 物流箱内为**配送方式单选**（如 京东快递 免邮 / 顺丰速运 +12），高亮当前项。
- 自提箱为**自提点**单选（按距离预选，可切换其他自提点）。
- 每箱的配送方式/自提点决定该箱物流能力与运费，运费计入本箱小计。

## 7. 支付方式 = 配送档案支付方式的交集 + 合并/分账

### 7.1 交集规则

- 页面支付区展示**所有被选箱的配送档案支付方式的交集**。
- **交集非空** → 任选交集内支付方式，**合并 1 单统一支付**。
- **交集为空** → 无公共方式，无法合并；页面**按箱分别展示各自支付方式**，提交按箱拆分为多个订单，各自支付。
- 顶部（交集为空时）红色提示框明确告知用户。

### 7.2 余额

- **余额**：共享钱包余额充足才可选合并；余额不足 → 该选项禁用，自动转分箱。

### 7.3 除余额外的合并与分账

- 微信支付 / 支付宝 / 货到付款：**合并 1 单统一收款**，实收**按商户(租户)分账**分别计入各商家账号。
- 即从"不选余额一律全拆"升级为：在线/货到付款也可合并 1 单，仅在**交集为空或余额不足**时才按箱拆单。

### 7.4 "在哪里选择合并/分箱"

- 页面**不放合并/分箱开关**。用户只在支付区选支付方式；系统依据「交集是否为空 + 余额是否充足」**自动判定**合并或分箱，并在支付区给出明确提示（"将合并为 1 单支付" / "交集为空，分箱按各自支付" / "余额不足，分箱支付"）。

## 8. 汇总（细化）

- 上部：**逐箱小计列表**（每箱拆到 商品 / 运费 / 券 的构成）。
- 中部：**按商户(租户)分账汇总**（每家商户一行的分账金额）。
- 底部：**应付款总额**（合并单）或各订单分项（拆单时）。
- 总账分项：商品合计（已选件数）、运费合计、优惠券合计、税额、应付款。

## 9. 局部结算后的归属（沿用老路）

- 提交的是"**所选箱子 + 所选商品行**"，而非一次全交。
- **选余额** → 全箱合并 1 单，从共享钱包统一扣款。
- **不选余额（在线/货到付款）** → 合并 1 单统一收款 + 按商户分账；若交集为空 → 按箱拆分各自支付。

## 10. 多语言（i18n）

- 全部固定文案走 i18n 字典，zh-CN / en-US 同步补充词条。
- country 默认值随语言（zh→CN / en→US）。
- 券名/档案名等多语言经既有 `localizeText` 逐级回退，前端 `VENDURE_LOCALE_MAP`（zh-CN→zh_Hans）沿用。

## 11. 边界场景汇总

| 场景 | 表现 |
|---|---|
| 单租户多档案（1 物流 + 1 自提） | 分开两张卡；支付交集决定合并/分箱 |
| 多租户多档案（2 商家 3 档案） | 按商家分区 → 每组并列各箱；商户分账汇总 |
| 3 档案各唯一绑定不同支付方式 | 交集空 → 顶部红条提示，每箱展示各自唯一支付，拆单各自支付 |
| 余额不足 | 余额选项禁用，自动转分箱支付 |
| 地址/联系人 > 10 条 | 自动分页，每页 5 条 |
| 无定位 | 不自动反查，用户手选省市区；fallback 城市名仅回填市 |

## 13. 防错与容错

- 整箱为主、部分/删除兜底；数量不可为 0。
- 每箱支付方式唯一且交集为空时不误合并。
- 国家必填先填充再校验；city 用 adcode 比对、空值不覆盖、提交回退。
- 局部结算所选集合为空时阻止提交并 toast。

## 15. 补充定稿决策（2026-09-02）

### 15.1 分账规划：台账先行、通道后置（Roadmap 两段式）

- **台账级（本期实现）**：合并单支付完成后，后端按 `merchantSplit` 写**分账台账**每商户一行（商户、订单、商品小计、运费、券抵扣、应计入金额）。各商户在运营后台可查分账流水。
- **通道级（后续独立 Roadmap，本期不做）**：真实把微信/支付宝货款分账打到各商户号。前置条件：各商户在支付通道配套开通服务商分账能力；需另行勘察对接，工作量判定为独立项目。
- 本期验收只承诺"台账分账正确"，不承诺通道分账。

### 15.2 未选箱/未选行 → 回流购物车

- 局部结算只对"所选 boxKey + 所选 lineIds"生成订单；**未被选中的箱/行回流入购物车**，不因部分结算而丢失。
- 实现要点（后端 `CheckoutSplitted` 处理局部行时）：
  1. 结算前先**记录被排除的未选 line（productVariantId + 数量快照）**；
  2. 订单生成/结算**成功后**，将排除项按数量 `AddItemToOrder` 加回活动购物车（幂等：成功即视为已回流，避免重复加购）；
  3. 若结算失败，则**不做任何移除**（保持 activeOrder 原状），防丢单；
  4. 回流商品的配送/券/库存资格重新走正常结算校验。
- 前端交互提示："剩余 N 件未结算，已放回购物车"。

### 15.3 货到付款分账时机：签收后入账

- **在线支付（微信/支付宝）**：**支付成功回调**时即写分账台账入账（款项已实收）。
- **货到付款（COD）合并单**：支付状态=待签收，**分账台账延迟到订单签收/收货确认后入账**（款项未实收不得提前入账）。签收事件触发按商户分账入账。
- 台账入账后各商户方可提现/对账；签收前各商户账目为"待入账"状态。

### 15.4 代销库存台账（独立表，新增 Roadmap）

**背景（事实核对）**：经查现有代码与文档，**不存在**"默认租户代销某租户商品、对应实际租户库存"的独立对账表。现有库存机制（Vendure `StockMovement` + `inventory-plugin.stockOnHand` + 可选 `redis-stock-plugin` 预扣）都只管"库存本身"，且 `redis-stock-plugin` 的 Redis key 仅含 `variantId`、**无租户/店铺维度**，无法对"货从哪个租户出"做对账。故本项为**新增设计**，非恢复旧实现。

**目的**：把"物的账"独立成表，与"钱的账（分账台账）"并行，可逐笔对账——默认租户卖某租户商品，卖出量与扣减该租户真实库存一一对应。

**建议表结构（Roadmap 初步，非本期实现）**：
| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `orderId` | 关联订单 |
| `occurredAt` | 发生时间 |
| `sellerChannelId` | 销售方/渠道（如默认租户） |
| `originTenantId` | 商品归属租户（`product.customFields.shopId` 溯源） |
| `productVariantId` | 商品变体 |
| `quantity` | 卖出数量（**正=扣减该租户库存，负=回滚/入库调整**） |
| `type` | 扣减 / 回滚 / 库存调整 |
| `settlementLedgerId` | 关联分账台账记录（钱账索引） |

**记账时机**：与分账台账同触发点（在线支付回调 / 货到付款签收后），或在下单扣库存时按租户维度写。**不含金额**（金额归分账台账），仅记货量。

**关联**：一次跨租户交易并行写两本账——货账（代销库存台账，扣原租户库存）+ 钱账（分账台账，钱进销售方/各商户），可经 `settlementLedgerId` 互相索引对账。
