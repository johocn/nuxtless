# 微信分享合成卡商品图高清化（nshop）

- 日期：2026-09-16
- 状态：已确认
- 范围：nshop（www.youshop.cn）微信转发卡片合成卡内商品图清晰度

## 1. 背景与问题

JS-SDK 签名修复（`2026-09-16-wechat-jssdk-signature-fix-design.md`）后微信卡片已有图，但用户反馈：
- 卡片显示的是 satori **合成卡**（优商铺品牌 + 标题 + 价格，白底），左侧商品图**发糊**。
- 根因：合成卡入图 `ogImageSrc` 使用 CDN **`w=400&q=60`** 压缩的小图，清晰度不足。
- 用户期望：**保留合成卡版式，卡内商品图换高清原图**。

## 2. 约束与现状

- 合成卡输出为 **PNG**（服务器无 sharp，不可用 jpeg），受微信分享缩略图 **~300KB 软上限**约束。
- 卡内图越清晰 → 整体 PNG 体积越大 → 存在超 300KB 被微信拒绝的风险。
- `ogImageSrc` 同时是 JS-SDK `imgUrl`（好友分享图）数据源；好友/朋友圈**统一同图**，不分图配置。
- 签名次数限制弊端：经查 zhao-sso 后端（`strapi/plugins/zhao-sso/server/src/services/sso-wechat.ts`）已用 `tokenCache`/`ticketCache` 缓存全局 access_token 与 jsapi_ticket（过期前 60s 复用）→ **签名接口不会高频打微信，该弊端已在服务端化解，前端无需改动**。

## 3. 设计

将 `ogImageSrc` 入图压缩参数从 `w=400&q=60` **上调以提升清晰度**，并通过**实测抓卡**迭代求"清晰且整体卡 ≤300KB"的平衡点。

- 起点建议 `w=800&q=80`；迭代区间 w∈{800, 600}, q∈{85..70}。
- 判据：合成卡 PNG 体积 ≤ 307200 字节；且 Read 目检商品图清晰（对比模糊）。
- 合成卡版式（`ProductCard.satori.vue`）、好友/朋友圈统一图策略不变。

## 4. 变更文件清单

- `layers/base/app/pages/product/[slug].vue`：`ogImageSrc` 入图参数（唯一改动文件）

## 5. 验证计划

1. 本地构建 → 起服务抓**有图且图片清晰的商品**（如 `温泉门票`）合成卡 PNG，检查体积 ≤300KB 且卡内商品图清晰；必要时下调参数重复，直至命中平衡点。
2. 回归：无图商品 `hotel-suite-test` 合成卡仍走兜底图、非空白。
3. 提交 → 部署（`scripts/deploy.mjs`）→ 线上复核体积。
4. 真机微信转发复核 + 手机截图（390×844）补操作手册。

## 6. 不做事项

- 好友/朋友圈分图配置（用户已选统一同图）。
- 新增图片资源/CSS 改版：保持现版式。
- 前端签名结果短缓存：server 已缓存，无必要，不做。
