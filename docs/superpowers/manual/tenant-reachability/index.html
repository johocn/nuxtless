一、功能说明

补齐多租户「永久可达」的三块缺口，让用户无论通过 渠道前缀 URL、店铺自有域名 还是 失效链接 进入，都能落到正确的店铺，且不出现白屏 / 空导航：

  • 全局错误页：区分「店铺不存在」与「页面不存在」两类 404，以及 500；自带站点外壳、多语言文案与恢复出口（返回首页 / 选择其他店铺）。
  • 域名直达：店铺自有域名命中渠道、且 URL 未带租户段时，服务端 301 归一为 /<code>/原路径，使站内链接天然带租户前缀（域名不变）。
  • 页头店铺切换器：桌面在页头右侧、移动端在抽屉内，与城市选择器并列；切换走整页导航，彻底重置渠道态（购物车 / 城市 / GQL 头）。
  • vshop 对齐：?tenant=<不存在> 由原「静默回退默认店」改为明示弹窗告知，与 nshop 的 404 行为一致。
  • 店铺清单 GQL：新增公开查询 shopChannels，供页头切换器与错误页「选择其他店铺」共用（单点数据源）。

二、租户解析机制（收敛到一处）

层级来源实现位置触发条件 / 结果
1. 路径首段/<locale?>/<code>/…server/middleware/tenant.ts首段（跳过 i18n 前缀）命中已知渠道 → 写 event.context.tenant，放行
2. 访问域名渠道 customDomainsserver/utils/tenant-registry.ts#resolveTenantByDomain首段未命中 → 按 host 解析；命中非默认渠道 → 301 到 /<locale?>/<code>/原路径
3. 平台默认店__default_channel__同上（默认渠道返回 null）域名绑定的是默认渠道 → 不 301（默认店本就不带前缀，零回归）
4. 未命中—layers/base/app/middleware/tenant.global.tsVue 路由层判定 404，data.kind = "shop-not-found"（逻辑页前缀不匹配 → page 版式）
状态触发条件表现
200首段命中渠道（或平台默认店无前缀）正常渲染该店铺
301域名命中非默认渠道，且 URL 未带租户段同域跳 /<code>/…（/en/product/x → /en/<code>/product/x，语言前缀保留在租户段之前）
404首段是租户段但渠道不存在/停用错误页「店铺不存在」（店铺版式）
404已知租户段下路径不匹配错误页「页面不存在」（页面版式 + 推荐店铺）
绝不 301 的排除清单（server/middleware/tenant.ts）：/_（/_nuxt/、/_ipx/、/_og/）、/api/、/shop-api、/admin-api、/images/、/static/、/assets/；带扩展名的请求（favicon.ico、robots.txt、sitemap.xml 等）与明确声明非 HTML 的请求一律放行。

三、店铺清单 GraphQL（数据源）

切换器与错误页共用同一份公开查询（无需鉴权），定义于 layers/base/gql/queries/tenant.gql，由 nuxt-graphql-client 生成 SDK 函数 GqlShopChannelsForSwitcher()，经 useTenantSwitcher() 消费：

query ShopChannelsForSwitcher {
  shopChannels { code token name tenantNo isOfficial isDefault }
}

页头切换器采用按需懒加载（打开面板时才取数），避免 setup 期异步取数造成的页头水合失配。

六、vshop 未知租户明示化（与 nshop 对齐）

入口：e.joho.cn/?tenant=<code>。当 <code> 不存在或已停用时：

  1. 仍回退到平台默认店（保证页面可用，不停在占位态）；
  2. 弹出模态框：「店铺不存在 / 店铺「<code>」可能已更名或停用，已为你切换到平台默认店铺。」，按钮「知道了 / 选择其他店铺」；
  3. 点「选择其他店铺」→ 移除 URL 上的 ?tenant 并 reLaunch 到首页，由页头 TenantBar 重新选择。

实现：vshop/src/stores/tenant.ts 新增 tenantInvalid 标记并在 initTenant() 失败时记录原始 code；vshop/src/App.vue 在 initTenant() 与 openTenantGate() 之间弹提示。

七、后台操作说明

7.1 给渠道配置自有域名（域名直达）

  1. 在 Vendure 后台渠道设置中，为该渠道的 customFields.customDomains 填入域名（如 shop.example.com）。
  2. 在部署侧把该域的 nginx server_name 指向 nshop 实例（默认店域名无需配置）。
  3. 生效窗口：nshop 侧域名解析按 host 做 60s 正/负缓存（含负向缓存），最长 60 秒后自动生效；如需立即生效见 §7.3。
  4. 验收：访问 https://shop.example.com/product/x → 应 301 到 https://shop.example.com/<code>/product/x。

7.2 停用渠道

在后台停用（或删除）渠道后：该 code 的 URL 将返回 404 店铺不存在，错误页给出「返回首页 / 选择其他店铺」出口；vshop 侧 ?tenant=<该 code> 将弹明示提示并回退默认店。租户表为 60s SWR，缓存未过期前最长有 60 秒窗口仍可访问。

7.3 让新建/停用渠道立即生效

店铺清单走前端 GQL 直连后端（实时）；真正受 60s SWR 影响的是路由解析。入口有两处：

  • 页头切换器 / 错误页「选择其他店铺」：切换动作前会自动打 /api/tenant/resolve?code=<code>&fresh=1 强制刷新租户表（带 5s 频控，防高频刷爆后端）。
  • 手动触发：curl "https://www.youshop.cn/api/tenant/resolve?code=<code>&fresh=1"。

7.4 回滚

  • nshop：git revert 相关提交 → node scripts/deploy.mjs（本地构建 → scp → pm2 restart nshop）。
  • vshop H5：把 .../sites/e.joho.cn/index.bak_<epoch> 备份目录覆盖回站点目录（见 vshop 手册 §6.4）。
