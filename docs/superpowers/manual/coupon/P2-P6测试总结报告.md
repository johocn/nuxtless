## 二、逐项详情

### P2 会员等级（memberLevel）拦截

- **现象**：claim / grant / apply 三处均无 `memberLevel` 校验，高等级门槛券低等级用户也能领/用。
- **根因**：后端未接入会员等级判定。
- **修复**：新增 `assertCouponMemberLevel()` / `couponMeetsMemberLevel()`，三处接入；`grant` 单条结果 `reason = MEMBER_LEVEL_BLOCKED`。
- **上线**：已随本次发布上线，线上验证 memberLevel=null 券可正常领（UNUSED）。
- **代码点**：`vendure/packages/coupon-plugin/src/coupon.service.ts`。

### P3 领券中心过滤 claimable=false

- **现象**：`couponCentre` 未过滤 `claimable=false`，凭码券/非自助领取券混入领券中心。
- **根因**：own / extra 两分支均未加 `claimable` 过滤。
- **修复**：两分支均补 `claimable = true` 条件。
- **上线**：线上实测 `couponCentre` 仅返回 claimable 券（P3 生效）。
- **代码点**：`coupon.service.ts` `couponCentre()`。

### P4 折扣净价/含税口径差 13%

- **现象**：`discounts[].amount` 为净价口径，与含税合计存在 13% 差值，疑似抵扣金额错误。
- **判定**：**非 bug**。抵扣实数正确；前端改用 `amountWithTax` 与含税合计同域展示，净价差是正确税额重算。
- **动作**：文档标注口径，无需改代码。

### P5 admin 建券 input 多语言支持

- **现象**：admin create/update 的 `CouponTemplateInput` 仅 `name: String!`，无法传入多语言文案（`nameZh/nameEn` 等）。
- **根因**：schema input 字段缺失多语言文字段。
- **修复**：input 增加 `nameZh/nameEn/descZh/descEn`，后端 `applyMultilingualInput()` 合并为 `LocalizedText` 对象（保留既有其它语言）。`name` 仍为纯字符串兼容。
- **代码点**：`coupon.service.ts` `createTemplate`/`updateTemplate`/`applyMultilingualInput()`；`plugin.ts` schema。

### P6 真实下单 → USED → RETURNED 全流程闭环

- **背景（初始判定）**：默认商城(youshop)存在「券←→商品同店」硬规则（`isDefaultMallChannel` 只算 `lineHasShopId` 本店商品行），在库可加购变体均属其它店，与可领券不匹配 → `applyCouponToOrder` 抛 `COUPON_SCOPE_MISMATCH`，一度判定「环境限制不可闭环」。
- **新解法**：创建**平台券（`shopId = null`）**——`lineHasShopId()` 对 `shopId == null` 恒返回 `true`，即对任意可加购商品行均匹配，从而绕过同店限制。
- **实测闭环（线上默认商城）**：
  1. 创建平台券（id=18，P6-闭环，FIXED 100，scope ALL，claimable）；
  2. 加购变体55（国信南山温泉门票）→ `applyCouponToOrder` 成功（无 SCOPE_MISMATCH）；
  3. `checkoutSplitted` 下单放置 → 触发 `OrderPlacedEvent → bindAsUsed` → **券62（C-8Z5A-7FL9）→ USED**（`usedOrderId=86`）；
  4. admin `cancelOrder` 取消订单86 → 触发 `OrderStateTransitionEvent(Cancelled) → returnCoupon` → **券62 → RETURNED**（`usedOrderId` 清空为 null）。
- **结论**：`OrderPlaced→bindAsUsed` 与 `Cancelled→returnCoupon` 事件监听**全链路在线可用**；「店券挂他店商品」受限属业务语义而非 bug；此前「不可闭环」判断被推翻。
- **复测 harness**：
  - USED 段：`scripts/_p6_flow.mjs`
  - RETURNED 段：`scripts/_p6_cancel.mjs`
- **重要技术点**：PaymentAuthorized → Cancelled 不可直接 `transitionOrderToState('Cancelled')`（受 `checkAllItemsBeforeCancel` 守卫拦截，报 transition error）；须调用 admin `cancelOrder`，先取消全部订单项再转 Cancelled。
- **残留环境限制（非券 bug）**：channel 92（测试渠道）无可用配送方法，结算配送不可达（订单无法推进到可勾选券的结算环节），需完整结算环境复测，已如实标注。
