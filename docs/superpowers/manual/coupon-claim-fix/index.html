领券中心领取失败「报错 26」

t2 租户领券中心点击「立即领取」弹出「领取失败 / 26」，未发起任何网络请求即同步报错；本次定位并修复根因。

项目：nshop 租户：t2（二月兰会员） 站点：www.youshop.cn

① 问题现象

在领券中心页面，登录状态下点击任意「立即领取」，页面底部弹出一条错误提示：

报错内容领取失败
26
  • 报错为纯数字 26，无其它文案；
  • 抓包确认该次点击并未向 /shop-api 发起任何 claimCoupon 请求——即请求在发出前就在前端同步抛错，被 catch 捕获后提示。

② 根因定位

给前端 resolveClient() 加日志后，捕获到真实异常为：

[claim] error {"code":26} | msg= 26
stack: SyntaxError: 26
    at al (.../CDgW9aFt.js)   // 错误工厂：new SyntaxError(code)
    at Ti (.../CDgW9aFt.js)   // al(pi.MUST_BE_CALL_SETUP_TOP)
    at tr (.../CDgW9aFt.js)   // if (getCurrentInstance()==null) throw 26

其中 26 = vue-i18n 错误码 MUST_BE_CALL_SETUP_TOP。`useCoupon.ts` 的 resolveClient() 在事件回调（点击领取）里直接调用 useI18n() 读取当前语言：

根因 vue-i18n 的 useI18n() 要求组件 setup 上下文；在点击/提交等事件回调中 getCurrentInstance() 为 null，因此抛出错误码 26（MUST_BE_CALL_SETUP_TOP）。列表加载在 onMounted（属于 setup 生命周期，能拿到实例）所以正常，唯有「点击领取」这类事件回调触发该同步错误，导致请求根本没发出去。

③ 修复方案

改动文件（nshop 前端）：

useCoupon.ts useMessages.ts 新增 readLocale() 并在 resolveClient() 中使用

  • 不再在事件回调里直接调用 useI18n()；改为优先读取全局 i18n 实例 useNuxtApp().$i18n.global.locale.value（该路径不依赖 setup 上下文）；
  • 取不到时兜底回退 zh-CN；
  • 读取结果仍用于 Accept-Language 头与 ?languageCode=（经 toVendureLocale 映射，如 zh-CN→zh_Hans），保证多语言回退正确。

useMessages.ts 存在完全相同的 useI18n() 隐患，一并修复，避免后续消息类功能在同一场景崩同款错误。
