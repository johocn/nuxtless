一、问题与修改概览

线上现象

  • 自提单需填写「领取人/联系电话」时，切换联系人入口藏在折叠的下拉菜单里，不点开根本看不到，用户常找不到切换/新增入口。
  • 同一自提配送档案可配置多个自提点，但切换需要把整列表平铺展示，占版面且不直观。

修改内容（纯前端）

  • 联系方式：改为「联系人 chips」直接可见、高亮当前选中（✓），点任意 chip 立即回填领取人/电话；末尾「＋ 新增联系人」清空输入进入新增态。仅登录用户显示切换池（有地址簿用真实地址，地址簿为空用示例联系人方便演示）；游客仍手填。
  • 多地提点：自提点改为「当前自提点概览卡 + 可展开选择器」——单选点时只显示概览；多自提点时出现「选择自提点」按钮，点开是搜索框 + 单选点列表，就近默认、换点即写库。
改动文件 CheckoutPickupContactBlock.vue（联系人 chips）· BoxPickupBlock.vue（多地提点展开器）· zh-CN.ts 等 i18n（新增词条）· useSampleAddressBook.ts（示例联系人池）。

四、多地提点切换验收

同一自提箱有多个自提点时，概览卡出现「选择自提点」按钮，点开是搜索框 + 单选点列表；单选点时只显示概览卡、无展开按钮。

切换成功

选择「自由大路 / 门店自提」其中一个后概览卡切至新点，主选中反馈即时生效；二月兰档案现正式绑定 2 点（配置与后台修复见「配送档案自提点管理修复」手册：pickup-profile-pickup-admin/index.html）。

五、验收结论

验收通过 自提单结算页「切换/新增联系人」改为直接可见的 chips（高亮 + ✓ + 点选回填 + 新增入口），未登录游客仍手填；同档自提点多时提供「选择自提点」展开切换器（搜索 + 单选、就近默认、换点即写库）。本修复均为纯前端改动，已随 node scripts/deploy.mjs 部署生产并在线回归通过。
