结算确认页改造：
复用订单详情组件（confirmation 版式）

把下单成功后的确认页主体改为复用订单列表「详情页」的渲染组件（状态卡 / 进度条 / 地址 / 商品 / 金额 / 订单元信息），同时保留确认页的感谢文案、打印回执、游客下单、支付返回、自提手机号补录等能力。

一、需求与方案

需求 下单成功后的确认页，想改成订单详情页的样式

  • 结算提交后的页面（/checkout/confirmation/:code）复用「订单列表点进去的详情页」组件渲染，保证视觉与信息一致。

方案确认 复用订单详情组件，保留原确认风格

  • 复用部分（新增 confirmation 版式）：订单主体由 OrderDetailConfirmation.vue 渲染——复用详情页各功能块：status / progress / redemption / address / items / pickup / totals / meta。
  • 保留部分：感谢文案头部（“订单已受理 / 感谢！”）、打印回执按钮、游客下单、支付回调返回（Stripe）、轮询等待、自提手机号补录（经 #phone-record slot 接入）。
  • 新确认版式不含“取消 / 再购 / 售后”操作块——刚下单场景不适用。
设计取舍 确认页是 client-only（.client.vue），天然支持游客。订单详情页虽带 account 中间件（需登录），但其渲染组件本身可复用；因此新建“确认版式”独立组件承载，而不跳转到需登录的详情页路由。

二、修改内容

2.1 新增 confirmation 版式枚举（order-config.ts）

export type OrderDetailLayout = "jd" | "classic" | "confirmation"; export function orderDetailLayout(cfg) { // 缺省/非法 → jd；confirmation 为结算确认场景专用版式 return cfg?.layout === "classic" ? "classic" : cfg?.layout === "confirmation" ? "confirmation" : "jd"; }

2.2 新增确认版式组件（OrderDetailConfirmation.vue）

  • 复用订单详情各功能块（与 OrderDetailJd 同一批组件），按后台 orderDetailConfig 的块显隐逐块渲染。
  • 保留确认头部（messages.shop.orderReceived + thankYou badge）、完成提示（orderThanks）与打印按钮（window.print()）。
  • 提供 #phone-record slot 承接确认页独有的自提手机号补录表单。

2.3 改造确认页（checkout/confirmation/[code].client.vue）

<OrderDetailConfirmation :order="order" :refresh="refresh"> <template #phone-record> …手机号补录表单… </template> </OrderDetailConfirmation>
  • 主体由手写区块改为渲染 OrderDetailConfirmation。
  • 游客下单、Stripe 支付返回、轮询等待（pollOrder）、手机号补录（GuestOrderLookup / GuestSetOrderCustomFields）逻辑全部保留。
  • 打印样式（@media print 隐藏 header/footer/.no-print）随组件保留。
注意（SSR / 组件名） confirmation 版式使用与详情页完全相同的功能块组件注册名，未引入新的自动注册前缀，避免 SSR 目录前缀命名导致的 hydration 空渲染问题。

2.4 自提单在确认页显示核销码

<OrderDetailRedemptionBlock v-if="pickup && visible('redemption')" :order="order" :config="config" :block="block('redemption')" />
  • 确认版式组件已渲染 OrderDetailRedemptionBlock，仅当订单为自提单（customFields.deliveryType === 'pickup'）且后台未关闭 redemption 块时显示。
  • 该块内部渲染 OrderRedemptionCard：请求 OrderRedemptionCode 取 6 位核销码 + 二维码，展示核销状态、自提点、有效期。
  • 物流配送单不显示核销码（redemption 块仅自提单展示）。

2.5 支付方式翻译成中文

// OrderMetaCard.vue：i18n 词条缺失回退显示 method code function paymentMethodLabel(method) { const key = `messages.order.paymentMethods.${method}`; const label = t(key); return label === key ? method : label; // 缺词条 → 原 code }
  • 订单元信息卡（OrderMetaCard.vue）中原先直接展示英文 code（如 balance-wallet），现改为按 messages.order.paymentMethods.* 词典翻译。
  • 词条已同步写入 zh-CN.ts（余额钱包 / Stripe支付 / 支付宝 / 微信支付 / 货到付款 等）与 en-US.ts，跟随当前 locale 切换。
  • 未知支付 code 走兜底：缺词条时 i18n 返回 key，直接回退显示原始 code，不报错。

3.3 本次新增验证：自提单核销码 ＋ 支付方式中文

  • 自提单（门店自提）订单的确认页应显示核销码卡片（6 位码＋二维码），并在“订单元信息”里支付方式显示中文；物流配送订单不显示核销码。
  • 支付方式：支付记录 method 为 balance-wallet 时应显示“余额钱包”，cash-on-delivery 且未收款时显示“待到店收款”。

验收结论 确认页已成功复用订单详情页组件渲染，订单状态／进度／地址／商品／金额／订单元信息与“订单列表→订单详情”视觉一致；确认页特有的“订单已受理／感谢！／打印回执”保留；游客下单、支付返回、轮询、自提手机号补录逻辑不受影响。自提单确认页显示核销码，支付方式显示中文。本栏截图取自生产实站 www.youshop.cn（2026-09-06 已部署，pm2 restart 后手机视口复核），自提单核销码与支付方式中文均生效。

块 key组件确认版式渲染说明
